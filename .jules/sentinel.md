## 2026-03-30 - DuckDB File-Reading Table Functions Bypass Read-Only SQL Guard
**Vulnerability:** DuckDB auto-detecting reader functions (`read_csv_auto`, `read_json_auto`), JSON file readers (`read_ndjson`, `read_json_objects`, `read_ndjson_objects`), file helper functions (`read_file`), parquet scanners (`parquet_scan`), and spatial file readers (`st_read`) were missing from `FORBIDDEN_FUNCTIONS` in `src-tauri/src/ai/guard.rs`. An attacker or AI query could execute statements like `SELECT * FROM read_csv_auto('/etc/passwd')` and bypass the syntactic read-only guard to read arbitrary local files.
**Learning:** DuckDB provides auto-detecting variants and aliases for common table functions (e.g. `read_csv_auto` in addition to `read_csv`). Relying on explicit function name lists requires accounting for driver-specific aliases and auto-detection variants.
**Prevention:** Whenever new database drivers or functions are introduced, audit all built-in file-reading, network-fetching, and system-interaction table/scalar functions and ensure they are added to `FORBIDDEN_FUNCTIONS` in `src-tauri/src/ai/guard.rs`.
